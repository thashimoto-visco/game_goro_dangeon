## 現在の描画接続

### プレイヤー

- `PLAYER_DRAW = { offsetX: -22, offsetY: -92, w: 44, h: 92 }`
- `sprites.player.idle`、`walk`、`attack` が `spritesheet.webp` の切り出しを使う。
- 上下方向は同じフレーム流用がある。
- ダメージや倒れ専用の明確な素材整理はまだ弱い。

### 敵

- `ENEMY_DRAW` に `slime`、`bat`、`golem`、`fallback` の描画サイズがある。
- 敵画像が読み込めない場合は `drawMonsterShape()` のCanvas図形に戻る。
- 現状の敵SVGはすべて `64x64` だが、これは現行値であり、今後の決定事項ではない。
- 待機アニメーションはまだ素材/基準として整理されていない。

### アイテム

- アイテム画像は `sprites.icons[itemType.icon]` で参照する。
- 床上では `20x20` で描画されている。
- `itemTypes` では `woodenSword` と `ironSword` が `weapon` アイコンを共有している。
- `riceBall` が `food`、`herb` が `potion` アイコンを使う。

### タイル

- タイル画像は `32x32` のSVGで、`TILE = 32` と一致している。
- 床/壁は `tileVariant(x, y, count)` による座標ベースの安定したバリエーション。
- 階段は `STAIRS_DRAW = { offsetX: 8, offsetY: 8, w: 16, h: 16 }` で小さめに描画されている。

### UI

- 画面は `canvas` と右側HTML UIの2カラム。
- HTML UIは `styles.css` の `--panel-bg`、`--panel-border`、`--panel-shadow` を使う。
- Canvas内にも持ち物メニュー、全滅画面があり、HTML UIとは別描画。
- Topic 1でレベル、経験値、自然回復が増えたため、ステータス欄の情報量が増えている。

## 現状課題

### プレイヤー

- 吾郎の素材はリッチだが、切り出しや方向流用が暫定的。
- 敵やタイルと比べて情報量が多く、画面内で浮いて見える可能性がある。
- Topic 2ではプレイヤー素材を作り直すより、足元、影、サイズ感の確認を優先する。

### 敵

- 3敵ともシンプルなSVGで、吾郎素材との密度差がある。
- コウモリの飛行感、ゴーレムの重さ、スライムの柔らかさをもっと出せる。
- 敵別の待機アニメーションがまだない。
- 画像フォールバック図形も、更新後の敵印象に合わせる必要がある。

### アイテム

- アイコンは種別共通で、個別アイテムの差は出ていない。
- 床上描画が `20x20` のため、細い武器は見落としやすくなる可能性がある。
- 薬草が `potion` アイコン扱いで、見た目が薬草なのか薬瓶なのかが曖昧。

### タイル

- 床/壁は最低限のバリエーションがあるが、部屋、通路、入口、壁角の意味づけはまだ薄い。
- 階段が `16x16` 表示で、重要物として少し弱い可能性がある。
- タイルの見た目を強めすぎると、敵やアイテムの視認性を邪魔する。

### UI

- HTML UIとCanvas内メニューが別系統の描画で、雰囲気差が出やすい。
- ステータス欄の情報量が増えたため、優先度のある見せ方が必要。
- ログ、持ち物、Canvasメニュー、全滅画面の色と枠を揃える余地がある。

## リッチ化優先順位

### 優先度1: 既存敵3種

理由:

- 階層別出現テーブルにより、1Fから5Fで敵種の差を見る機会が増えた。
- Topic 2の成果が最も分かりやすい。
- 後続の強敵、状態異常敵、特殊敵の基準になる。

対象:

- スライム。
- コウモリ。
- ゴーレム。

### 優先度2: 既存アイテム3系統

理由:

- Topic 1でアイテム出現テーブルが階層別になり、アイテム価値が上がっている。
- 食料、回復、武器はプレイ判断に直結する。
- 後続の追加アイテム用の基準になる。

対象:

- 武器系。
- 食料系。
- 回復系。

### 優先度3: タイルと階段

理由:

- 探索画面の印象を大きく左右する。
- ただし強くしすぎると敵/アイテムの視認性を落とすため、敵とアイテム更新後に調整する方がよい。

対象:

- 床。
- 壁。
- 階段。

### 優先度4: UI統一

理由:

- Topic 1で情報量が増えたため、最終的には整える必要がある。
- ただしゲーム画面側の見た目が変わってから合わせた方がよい。

対象:

- HTMLステータス欄。
- ログ。
- 持ち物欄。
- Canvas内持ち物メニュー。
- 全滅画面。

### 優先度5: 吾郎の再整理

理由:

- 吾郎はすでに最もリッチな素材を使っている。
- Topic 2で全面作り直しを始めると範囲が広がりすぎる。
- 敵、アイテム、タイルの更新後、足元、影、サイズ感の微調整として扱うのがよい。

対象:

- `PLAYER_DRAW`。
- スプライト切り出し。
- 足元と影。

## Step 2への引継ぎ

Step 2では、既存敵3種を先に扱う。

最初に決めるべきこと:

- スライム、コウモリ、ゴーレムの役割差。
- 各敵の見た目密度。既存の吾郎と同じ画面に並べても見劣りしない密度を目指す。
- 既存3敵のテイスト。怖さよりも、かわいらしい見た目を優先する。
- 接地型と飛行型の影の扱い。
- 敵待機アニメーションの最小方針。まずは2コマ相当でよい。
- `ENEMY_DRAW` と画像素材のどちらでサイズ感を調整するか。

まだ決めないこと:

- 新規敵追加用のひな形。
- 敵素材の最終キャンバスサイズ。
- 強敵のサイズ基準。
- 状態異常敵や特殊AIの見た目。

これらは、既存敵を実際にリッチ化し、ゲーム内で確認した後に整理する。

詳細: `step2-existing-enemy-graphics-rich-plan.md`
