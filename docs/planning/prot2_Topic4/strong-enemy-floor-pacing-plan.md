# Topic 4 詳細プラン: 強敵と階層メリハリ

作成日: 2026-07-10  
改訂日: 2026-07-10

## 目的

Topic 4では、通常遭遇とは明確に異なる「避けるか、準備して倒すか」を考える強敵遭遇を追加し、探索にメリハリを作る。

ここでいう「強敵」はモンスター種に永久に付く属性ではない。同じ敵でも、出現階層、個体補正、プレイヤーの想定成長度によって脅威度は変わる。たとえば「ミニ悪魔ちゃん」は5Fでは強敵枠で出現し、ゲームが先へ拡張された時には10F前後の通常敵として出現できる設計にする。

Topic 1の成長、Topic 2の敵追加基準、Topic 3のイベント部屋基盤を接続し、モンスター種と遭遇ランクを独立して増やせる土台を作る。

## 設計原則

### 強敵は敵種ではなく遭遇コンテキスト

- モンスターカタログは「その種が何者か」を定義する。
- 出現テーブルは「どの階層で、どのランクの個体として出るか」を定義する。
- 生成された敵個体は、今回の遭遇ランクと適用済み補正を持つ。
- 警告、オーラ、報酬、戦績判定は敵キーではなく遭遇ランクを見る。
- 同じモンスターを別階層で通常個体、強敵個体、将来はボス個体として再利用できる。

したがって `monster-catalog.js` に `role: "strong"` のような恒久属性は置かない。`ミニ悪魔ちゃんなら常に強敵`、`5Fなら常にこの敵` という分岐も `main.js` に書かない。

### 5Fは検証シナリオであり、システム上の前提ではない

Topic 4の最初の動作確認では5Fを節目階として使う。ただし、5F固定を生成ロジックへ埋め込まない。

- 5Fで強敵遭遇を100%にするのはMVPのテスト設定。
- 階層、出現率、敵種、遭遇ランクはテーブルから差し替え可能にする。
- テスト時は5F固定により遭遇確認を容易にする。
- 体験確認後は、5Fの出現率を下げる、別階層へ移す、候補を複数にする変更をデータだけで行える。
- 将来10F前後の通常敵テーブルへミニ悪魔ちゃんを追加できる。

### ランクと体感脅威度を分ける

`encounterRank` は報酬や演出を決める生成時の分類であり、プレイ中に変化させない。一方、実際に危険かどうかはプレイヤーのレベル、HP、装備でも変わる。

MVPでは次の二層で扱う。

1. 遭遇ランク: `normal` / `strong`。配置、個体補正、警告、報酬に使用する。
2. 体感脅威度: プレイヤーの現在状態からUI上の警告を将来調整できる余地を残す。ただしTopic 4では複雑な戦力計算を実装しない。

HPが減っただけで通常敵が強敵報酬を持つ、回復した瞬間に強敵でなくなる、といった不安定な仕様にはしない。報酬分類は生成時に確定させる。

## 現状整理

- 敵定義は `monster-catalog.js` に集約され、数値、画像、描画、モーション、フォールバック形状、ヒット演出をデータで追加できる。
- `monster-system.js` が敵定義の正規化と階層補正付きの敵生成を担当する。
- `dungeon-spawn-tables.js` は通常敵の階層別出現数と比率だけを持つ。
- 通常敵はスライム、コウモリ、ゴーレムの3種で、5F以降も同じ出現テーブルが続く。
- 敵が初めて視界に入ると「！」、遭遇ログ、共通SEが出る。
- 敵撃破時は経験値と撃破数が加算されるが、個別ドロップや遭遇ランク別戦績はない。
- 敵ごとの死因はカタログの `defeatText` から取得される。
- イベント部屋は1フロア最大1つで、開始部屋と階段部屋を避けて宝物部屋または回復の泉を配置する。
- 1マスは32pxで、画像は論理マスより上へはみ出して描画できる。

## 最小完成形

- 新規モンスター「ミニ悪魔ちゃん」を追加する。
- ミニ悪魔ちゃん専用の新規グラフィックスを制作する。
- 設定テーブル上、5Fに `strong` ランクのミニ悪魔ちゃんを1体出現させる。
- 5F固定はMVPの検証設定であり、汎用ロジックには階層番号や敵キーを埋め込まない。
- 強敵遭遇用の部屋は開始部屋、階段部屋を避け、階段への経路を封鎖しない。
- 強敵撃破は階段利用の必須条件にしない。
- 検証設定では5Fの宝物部屋／回復の泉抽選を強敵部屋へ置き換え、1フロア最大1特殊部屋を維持する。
- 強敵ランク個体には予兆、専用遭遇演出、個体補正、確定報酬を適用する。
- 将来の通常出現例として、10F前後の通常テーブルへ同じミニ悪魔ちゃんを追加できることをテストで示す。

- 永続的な討伐記録。

## 目標体験

1. 節目階へ降りると、通常階とは違う不穏さが短いログと音で伝わる。
2. 強敵部屋へ近づく、または入ると、戦う前に危険を理解できる。
3. ミニ悪魔ちゃんを視認すると、新しい敵との遭遇そのものが印象に残る。
4. 強敵ランク個体はオーラ、警告、数値によって通常ランク個体と見分けられる。
5. HP、レベル、武器、薬草を見て戦うか避けるか判断する。
6. 倒せば消耗に見合う経験値と報酬が得られる。
7. 将来、深層で通常ランクのミニ悪魔ちゃんに再会した時に、吾郎の成長を感じられる。

## 新規モンスター: ミニ悪魔ちゃん

### 役割

- Topic 4で初めて登場する完全新規シルエットの敵。
- MVPの5Fでは、先行出現する強敵ランク個体。
- 将来の10F前後では、通常ランクで出現可能な中層敵。
- 小柄だが魔力を感じる見た目とし、既存3種から世界を広げる。

### キャラクター方針

- 名前: ミニ悪魔ちゃん。
- テイスト: 怖さよりも、いたずら好きで生意気な小悪魔らしさを優先する。
- シルエット: 小さな角、大きめの耳または髪、短い翼、先端の尖った尻尾。
- 体格: 吾郎より小柄。ただし翼と角で横方向・上方向の輪郭を作る。
- 表情: 自信ありげな笑み。極端に幼児的または人間の子供そのものにはしない。
- 主色候補: 深い紫または赤紫。
- アクセント: 角と翼膜に暗色、目または魔力に黄〜橙。
- 通常敵との差は種の専用画像で、強敵ランクとの差はオーラ、バッジ、影、遭遇演出で表す。

同じミニ悪魔ちゃんを10Fで通常敵として使えるよう、画像自体に王冠、ボス専用台座、恒久的な「強敵」文字は描き込まない。

### ゲーム上の初期役割

ミニ悪魔ちゃんの素のステータスは「将来10F付近で通常敵として使う」ことを意識して定義し、5Fの強敵ランク個体には遭遇テーブル側の補正をかける。

```js
{
  key: "miniDevil",
  name: "ミニ悪魔ちゃん",
  defeatText: "吾郎はミニ悪魔ちゃんのいたずらに敗れた",
  messages: {
    floorPresence: "この階には、いたずらでは済まない気配がある……。",
    roomPresence: "羽音と小さな笑い声が聞こえる。",
    encounter: "ミニ悪魔ちゃんが現れた！",
    strongEncounter: "強敵のミニ悪魔ちゃんが現れた！",
  },
  stats: {
    baseHp: 10,
    baseAtk: 5,
    hpScale: 1.15,
    atkScale: 0.5,
    exp: 10,
  },
  asset: "assets/monster_mini_devil.svg",
  draw: { offsetX: -36, offsetY: -68, w: 72, h: 64 },
  motion: {
    cycle: 560,
    bob: 3,
    floatOffset: 1,
    shadowOffsetY: 7,
  },
  fallbackShape: {},
  burst: {},
}
```

値は実装開始時の候補であり、グラフィックスと5F戦闘確認後に調整する。

## 遭遇データ設計

### 遭遇ランク定義

敵種に依存しない汎用プロファイルとする。

```js
const encounterRankProfiles = {
  normal: {
    statMultiplier: { hp: 1, atk: 1, exp: 1 },
    guaranteedReward: null,
    presentation: null,
    countsAsStrongDefeat: false,
  },
  strong: {
    statMultiplier: { hp: 1.45, atk: 1.2, exp: 1.8 },
    guaranteedReward: "strongDefault",
    presentation: "strong",
    countsAsStrongDefeat: true,
  },
};
```

倍率は初期候補。整数丸め後の最終値を敵個体に保持し、戦闘中にプレイヤー状態によって変動させない。

### 強敵遭遇テーブル

新規 `dungeon-encounter-tables.js` または同等の小モジュールへ置く。

```js
const specialEncounterTables = [
  {
    id: "topic4-validation-5f",
    minFloor: 5,
    maxFloor: 5,
    chance: 100,
    roomType: "stronghold",
    entries: [
      { monster: "miniDevil", rank: "strong", weight: 100 },
    ],
  },
];
```

`id` にMVP検証設定であることを残す。汎用配置ロジックは `minFloor`、`maxFloor`、`chance`、`entries` だけを読み、5や `miniDevil` を知らない。

### 将来の通常出現例

正式な10F実装はしないが、次のデータを追加可能であることを設計・単体テストで確認する。

```js
{
  minFloor: 9,
  maxFloor: 11,
  count: [6, 8],
  entries: [
    { type: "golem", weight: 25 },
    { type: "miniDevil", rank: "normal", weight: 35 },
    // 将来追加する別モンスター
  ],
}
```

既存の通常スポーンテーブルでは `rank` を省略したら `normal` と解釈する。Topic 4完了時に9F〜11Fテーブルを本番設定へ入れる必要はない。

### 生成された敵個体

```js
{
  // 既存項目
  encounterRank: "strong",
  encounterId: "topic4-validation-5f",
  baseMonsterKey: "miniDevil",
  rewardProfile: "strongDefault",
}
```

カタログ全体は複製しない。生成時に種の階層補正を計算し、その後に遭遇ランク倍率を1回だけ適用する。

## イベント部屋との接続

MVP設定のフロア生成順は次を候補とする。

1. マップ、開始位置、階段位置を決める。
2. 現在階に該当する特殊遭遇テーブルを引く。
3. 特殊遭遇が成立したら、イベント候補部屋から `stronghold` を1つ確保する。
4. 特殊遭遇が不成立なら、従来の宝物部屋／泉を抽選する。
5. 通常敵を配置する。
6. 遭遇テーブルで選ばれた敵種とランクを強敵部屋へ配置する。
7. 通常アイテムとイベント報酬を配置する。

候補部屋条件:

- 開始部屋、階段部屋ではない。
- 開始部屋、階段部屋と矩形が重ならない。
- 最低5×4マス。通常イベントより小さい部屋も候補にしつつ、開始部屋と階段部屋は使わない。
- 敵の周囲に最低2マス以上の移動可能マスが残る。
- 配置に失敗したら、別座標、別候補部屋の順で再試行する。

有効な候補がないフォールバックレイアウトでは無理に配置しない。生成破綻より進行可能性を優先し、テストでスキップ率を監視する。

## 警告と演出

### 敵ごとのメッセージ定義

予兆と遭遇メッセージは、敵ごとに `monster-catalog.js` の `messages` へ設定できるようにする。羽音や笑い声のような種固有表現を、遭遇ランクの共通文言へ置かない。

対応するメッセージ:

- `floorPresence`: その敵を含む特殊遭遇が配置された階へ入った時。
- `roomPresence`: その敵がいる特殊部屋を初めて発見した時。
- `encounter`: 通常ランク個体を初めて視認した時。
- `strongEncounter`: 強敵ランク個体を初めて視認した時。

同じ敵でもシナリオごとに文言を変えたい場合は、特殊遭遇テーブルのentryに `messages` を指定して上書きできるようにする。

```js
{
  monster: "miniDevil",
  rank: "strong",
  weight: 100,
  messages: {
    floorPresence: "この階には、いたずらでは済まない気配がある……。",
    roomPresence: "羽音と小さな笑い声が聞こえる。",
  },
}
```

メッセージの解決優先順位:

1. 特殊遭遇entryの `messages`。その遭遇シナリオ専用の上書き。
2. モンスターカタログの `messages`。敵種ごとの標準文言。
3. 遭遇ランクの共通テンプレート。例: `強敵の${enemy.name}が現れた！`。
4. 通常遭遇の共通テンプレート。例: `${enemy.name}が現れた！`。

未定義項目があっても空文字や `undefined` をログへ出さず、次の優先順位へフォールバックする。メッセージ文字列の組み立てや選択は汎用関数へ集約し、敵キーによる条件分岐を作らない。

### 予兆

警告は上記の優先順位で解決した文言を使い、各段階1回だけ出す。

1. 節目階開始時: `この階には、いたずらでは済まない気配がある……。`
2. 強敵部屋の初回発見時: `羽音と小さな笑い声が聞こえる。`
3. 強敵ランク個体の初回視認時: `強敵のミニ悪魔ちゃんが現れた！`

文言は `miniDevil` 専用部分と `strong` ランク共通部分を分ける。通常ランクで視認した場合は `ミニ悪魔ちゃんが現れた！` とし、強敵警告を出さない。

### 視覚表現

- ミニ悪魔ちゃん固有: 専用SVG、翼を使った浮遊モーション、紫系の粒子。
- 強敵ランク共通: 赤紫の淡いオーラ、大きい警告マーク、広めの影、HPバーの縁取り。
- 強敵部屋: 暗い赤紫の淡い床光。
- 強敵撃破: 通常より少し長いヒットストップ、強めのカメラ揺れ、金色の `強敵撃破` 浮遊文字。

強敵だから画像を拡大する設計には依存しない。ミニ悪魔ちゃんは小柄なキャラクター性を維持し、ランク差は周辺演出で示す。

### 音

既存と同じWeb Audio生成音を使う。

- `strongPresence`: 部屋発見向けの低い短音。
- `strongEncounter`: 通常遭遇より緊張感のある2〜3音。
- `strongDefeat`: 通常撃破音に短い上昇音を重ねる。

音OFF時でもログと視覚演出で情報が欠けないことを必須とする。専用BGMは今回は追加しない。

## 撃破報酬

- 種の基礎経験値へ `strong` ランクの経験値倍率を適用する。
- 確定ドロップは、倒したマスまたは隣接空きマスへ1個置く。
- 報酬候補: 薬草40%、鉄の剣35%、おにぎり25%。
- 木の棒は強敵報酬から外す。
- 持ち物が満杯でも床に残す。
- 配置不能時は近傍の空きマスを探索し、それでも置けない場合はログを残して進行を継続する。
- `state.stats.strongDefeated` は `countsAsStrongDefeat` を見て加算する。

報酬はミニ悪魔ちゃん固有ではなく遭遇ランク側に置く。将来、通常ランクのミニ悪魔ちゃんを倒しても強敵確定報酬は出ない。

## 新規グラフィックス制作

グラフィックス制作はTopic 4の必須スコープとする。仮図形だけで完了扱いにはしない。

### 必須成果物

| パス案 | 内容 | 仕様と確認点 |
| --- | --- | --- |
| `assets/monster_mini_devil.svg` | ミニ悪魔ちゃんの専用敵画像 | 透明背景。角、翼、尻尾で既存3敵と異なる輪郭。通常ランクでも使える中立的な本体デザイン。72×64px前後のゲーム内描画で顔と姿勢が読める。 |

### 制作工程

1. 既存の吾郎、スライム、コウモリ、ゴーレムを並べ、色、線、陰影、顔の情報量を確認する。
2. ミニ悪魔ちゃんのシルエット案を2〜3案作る。
3. 32pxグリッド上へ仮配置し、角、翼、尻尾が潰れない案を選ぶ。
4. SVGを制作し、少ない色数、段階的な陰影、明瞭な輪郭に整える。
5. `monster-catalog.js` へ接続し、浮遊位置、足元影、描画サイズを調整する。
6. 通常ランク表示と強敵ランクのオーラ付き表示を両方確認する。
7. 暗い5F色調、被弾点滅、HPバー、撃破演出との重なりを調整する。
8. 画像読み込み失敗用の `fallbackShape` も同じシルエットへ寄せる。

### アート受け入れ条件

- スライム、コウモリ、ゴーレムの派生に見えない。
- 色を除いても、角、翼、尻尾の輪郭でミニ悪魔ちゃんと分かる。
- 吾郎の隣で小柄に見えるが、敵として見落とさない。
- 既存のかわいらしいテイストから極端に外れない。
- 通常ランクでは中層の通常敵として成立する。
- 強敵ランクでは本体を描き直さなくても、オーラと警告で危険度が伝わる。
- 暗い背景でも顔、目、翼、足元が埋もれない。
- 高DPI表示でも輪郭がぼやけすぎない。

### コード描画で対応するもの

- 強敵ランクの警告マーク。
- 強敵ランクのオーラ。
- 強敵部屋の床光。
- 強敵ランクのHPバー装飾。
- 撃破時の浮遊文字と粒子。

## 実装ステップ

以下は1バッチ内の内部実装順であり、各Step単体を完成版としてリリースしない。

### Step 1: 遭遇ランク基盤

- `normal` / `strong` の汎用プロファイルを追加する。
- 通常スポーンのランク省略時は `normal` とする。
- 敵生成時に種の階層補正と遭遇ランク補正を順に適用する。
- 通常敵3種の生成結果が変わらないことをテストする。

完了条件:

- 任意の敵種を任意階層で `normal` または `strong` として生成できる。
- `main.js` に敵キーや5F専用分岐を追加しない。

### Step 2: ミニ悪魔ちゃんのデータとグラフィックス

- キャラクター案を作成し、既存画面上で選定する。
- 専用SVGとフォールバック形状を制作する。
- カタログへ数値、描画、モーション、死因、粒子を追加する。
- 通常ランク表示を先に完成させる。

完了条件:

- 専用グラフィックスがゲーム内で表示される。
- 通常敵として表示しても不自然なボス装飾がない。
- 既存敵の追加時と同じデータ駆動パイプラインを使う。

### Step 3: 特殊遭遇テーブルと配置

- 汎用の特殊遭遇テーブルを追加する。
- MVP設定として5F・100%・ミニ悪魔ちゃん・`strong` を定義する。
- 強敵部屋、敵、通常配置の衝突を回避する。
- 配置失敗時の安全なフォールバックを実装する。

完了条件:

- MVP設定では通常レイアウトの5Fに強敵ランク個体が1体出る。
- 設定を7Fへ変えればコード変更なしで出現階を移せる。
- 敵を別種へ変えても同じ演出・報酬が機能する。

### Step 4: 予兆、遭遇、ランク表現

- 階開始、部屋発見、初回視認の段階演出を追加する。
- `strong` ランク共通の警告、オーラ、HPバー、SEを追加する。
- 通常ランクのミニ悪魔ちゃんには強敵演出が出ないことを確認する。
- 通常敵との同時視認時は強敵遭遇演出を優先し、音の重複を避ける。

### Step 5: 撃破報酬、戦績、死因

- 共通撃破処理へ遭遇ランクに基づく追加報酬フックを設ける。
- 強敵経験値倍率、確定ドロップ、専用撃破演出を実装する。
- `strongDefeated` を追加し、リトライ時に初期化する。
- 死因は敵種の文言を維持し、必要なら強敵ランク用の接頭辞を定義可能にする。

### Step 6: バランスと拡張性検証

- レベル2〜4、武器なし／木の棒／鉄の剣、薬草0〜2個で5F強敵戦を確認する。
- `strong` 倍率を1項目ずつ調整し、通常敵や成長テーブルは原則変更しない。
- テスト内で10F相当の通常ランク・ミニ悪魔ちゃんを生成する。
- 同じ敵種でも遭遇ランクによって数値、演出、報酬が変わることを確認する。
- README、手動テスト、完了メモを更新する。

バランス目安:

- レベル3＋木の棒＋HP十分なら、薬草0〜1個で勝てる可能性がある。
- レベル2＋武器なし＋HP半分では、戦うのが明確に危険。
- 鉄の剣があっても無傷では勝てない。
- 撃破経験値だけで複数レベル上がらない。
- 回避を選んでも先へ進める。

## 自動テスト計画

### モンスター／遭遇ランク

- ランク省略時に `normal` になる。
- 同じミニ悪魔ちゃんを5F `strong` と10F `normal` で生成できる。
- `strong` 個体だけにHP、攻撃、経験値倍率が適用される。
- `strong` 個体だけが確定報酬と強敵戦績の対象になる。
- ランクが違っても画像、種名、種固有死因は同じ定義を参照する。
- 不明ランクは例外ではなく安全な既定値へフォールバックする。
- 敵ごとの `floorPresence`、`roomPresence`、`encounter`、`strongEncounter` を取得できる。
- 特殊遭遇entryのメッセージがカタログの標準文言より優先される。
- entryとカタログで未定義なら、ランクまたは通常遭遇の共通テンプレートへフォールバックする。
- 未定義メッセージによって `undefined` や空のログ行が表示されない。

### 特殊遭遇配置

シード固定で複数回生成し、次を確認する。

- MVP設定では1Fから4Fに特殊遭遇がない。
- MVP設定では通常条件の5Fに特殊遭遇が1つ。
- テーブルの階層を変更すると出現階も変わる。
- テーブルの敵キーを変更しても配置できる。
- 特殊遭遇が1フロア最大1つ。
- 敵が開始位置、階段、イベントオブジェクト、通常敵、アイテムと重ならない。
- 配置不能時に無限ループせず、進行可能なフロアを返す。
- 同じシードと設定では同じ配置になる。

### 回帰

- 変更／追加JSすべてに `node --check` を実行する。
- 既存の構造テストが通る。
- 通常ランクの既存3敵の数値、描画、遭遇ログ、報酬が変わらない。
- 宝物部屋と回復の泉が特殊遭遇のない階で従来どおり出る。

## 手動テスト

### グラフィックス

- ミニ悪魔ちゃんが既存3敵とシルエットで区別できる。
- 角、翼、尻尾、表情がゲーム内サイズで読める。

- 経験値と報酬が1回だけ付与される。

- 音OFFでもログと視覚演出で強敵を認識できる。
- リトライで遭遇、戦績、警告状態が初期化される。

## リスクと対策

### 5F専用コードへ戻ってしまう

対策:

- 出現階はテーブルだけに置く。
- 配置関数は現在階とテーブルを引数で受け取る。
- 7Fへ移動するテストと、別敵種へ差し替えるテストを受け入れ条件に含める。

### ミニ悪魔ちゃんが永久に強敵扱いされる

対策:

- カタログへ強敵フラグを置かない。
- 描画本体へ強敵専用装飾を描き込まない。
- 5F強敵と10F通常の生成テストを必須にする。

### プレイヤー状態でランクを変えると報酬が不安定になる

対策:

- 遭遇ランクと報酬は生成時に確定する。
- 現在HPなどから求める体感脅威度は将来のUI補助に限定する。
- ランクとプレイヤー相対評価を同じフィールドで扱わない。

### 新規敵が既存3種と同じ印象になる

対策:

- 既存種の派生ではなく、角、翼、尻尾を持つ新規シルエットにする。
- 実装前に複数案を32pxグリッド上で比較する。
- 専用SVGの完成をTopic 4の完了条件にする。

### 強敵が単なる数値の壁になる

対策:

- 予兆、ランク表現、報酬を数値調整と同じ優先度で実装する。
- HPだけを過剰に増やさず、戦闘ターン数と薬草消費で調整する。
- 特殊AIは追加せず、まず準備判断の体験を評価する。

### `main.js` に敵別・ランク別分岐が増える

対策:

- 種固有表現はカタログ、ランク表現はランクプロファイルへ置く。
- 特殊遭遇の抽選と配置は小モジュールへ分離する。
- 遭遇、撃破、報酬は汎用フックとして作る。
