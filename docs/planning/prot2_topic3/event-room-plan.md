# Topic 3 詳細プラン: イベントと特殊部屋

作成日: 2026-05-27

## 目的

Topic 3では、通常の部屋、敵、アイテム、階段だけで進む探索に、低確率で「何か起きる」変化を加える。

最初からイベント種類を増やしすぎず、既存のフロア生成、敵配置、アイテム配置、ログ、SE、描画演出に自然につながる小さな仕組みとして実装する。最低ラインは、宝物部屋と回復の泉が実際に出現し、プレイヤーが見た目とログで気付けることとする。

## 現状理解

- フロア生成は `generateFloor()` にまとまっている。
- 部屋は `rooms` 配列として作られ、開始部屋は `rooms[0]`、階段部屋は `rooms[rooms.length - 1]` に置かれる。
- 敵配置は `placeEnemies(rooms)`、アイテム配置は `placeItems(rooms)` で行う。
- アイテム、敵、階段、プレイヤーの重なりは `isItemPlacementBlocked()` と `isEnemyPlacementBlocked()` で避けている。
- プレイヤー移動後の処理は `tryMove()` にあり、拾得、階段移動、ターン経過がここでつながっている。
- ログは `addLog()`、SEは `playSound()`、一時演出は `effects`、`startFlash()`、`startCameraShake()`、`addFloatingText()` が使える。
- 描画は `drawMapLayer()`、`drawStairsLayer()`、`drawItemLayer()`、`drawActorLayer()`、`drawEffectsLayer()` の順で行われている。
- Topic 2で、特殊部屋の見た目はタイル差よりも照明、色味、淡い光、イベント用オブジェクトで出す方がよいと整理されている。

## 目標体験

- フロアを歩いていて、たまに通常部屋とは違う雰囲気の部屋を見つける。
- 宝物部屋では、通常より少しうれしいアイテム配置がある。
- 回復の泉では、踏む、または隣接して触れることでHP回復の救済が起きる。
- イベントは便利だが、ゲームを壊すほど強くない。
- イベント発生はログ、SE、見た目で分かる。
- イベントが出ないフロアも普通に成立する。

## 実装方針

### イベント部屋の持ち方

`state` にイベント用の配列を追加する。

```js
state.eventRooms = [];
state.eventObjects = [];
```

`eventRooms` は部屋単位の情報を持つ。

```js
{
  id,
  type: "treasure" | "spring",
  room: { x, y, w, h, cx, cy },
  discovered: false,
}
```

`eventObjects` はマス上に表示または発火する対象を持つ。

```js
{
  id,
  type: "spring",
  x,
  y,
  used: false,
}
```

宝物部屋は部屋タグとアイテム配置だけでも成立する。回復の泉は、プレイヤーがそのマスに乗った時に発火するオブジェクトとして扱う。

### 生成順

Topic 3では、既存生成への影響を小さくするため、以下の順にする。

1. `generateFloor()` で通常通り部屋を作る。
2. 開始部屋と階段部屋を決める。
3. `selectEventRooms(rooms)` で特殊部屋候補を決める。
4. `placeEventObjects()` で泉などを置く。
5. `placeEnemies(rooms)` で敵を置く。
6. `placeItems(rooms)` で通常アイテムを置く。
7. `placeEventRewards()` で宝物部屋の追加アイテムを置く。

宝物部屋報酬を通常アイテムの後に置くと、通常生成に埋もれにくい。ただし配置時は既存の重なり判定にイベントオブジェクトを加える。

### イベント抽選

最初は1フロアに最大1イベントを基本にする。

- 1F: 低確率。初回プレイの学習を邪魔しない。
- 2Fから3F: 宝物部屋または回復の泉が低確率。
- 4F以降: 少しだけ確率を上げる。

暫定案:

```js
const floorEventTables = [
  { minFloor: 1, maxFloor: 1, chance: 18, entries: [{ type: "treasure", weight: 60 }, { type: "spring", weight: 40 }] },
  { minFloor: 2, maxFloor: 3, chance: 28, entries: [{ type: "treasure", weight: 55 }, { type: "spring", weight: 45 }] },
  { minFloor: 4, maxFloor: 99, chance: 35, entries: [{ type: "treasure", weight: 50 }, { type: "spring", weight: 50 }] },
];
```

`chance` はパーセント扱いにする。イベントが出るか、どの種類か、どの部屋かを分けて抽選する。

### 部屋候補

イベント部屋候補からは以下を除外する。

- 開始部屋。
- 階段部屋。
- 小さすぎる部屋。
- すでに別イベントが付いている部屋。

部屋サイズは、暫定で `w >= 6 && h >= 5` を目安にする。候補がない場合はイベントなしにする。

## イベント仕様

### 宝物部屋

役割:

- 探索中の小さな報酬。
- 通常部屋と違う見た目のアクセント。
- Topic 5の追加アイテムやレアアイテムの受け皿。

初期仕様:

- 部屋の床に淡い金色の照明を重ねる。
- 部屋内に追加アイテムを2個置く。
- 追加アイテムは通常テーブルより少しだけ良い比率にする。
- 初回侵入時にログとSEを出す。

暫定報酬:

- 1Fから3F: 薬草、おにぎり、木の棒、低確率の鉄の剣。
- 4F以降: 鉄の剣を少しだけ出やすくする。

ログ案:

- `宝物の気配がする部屋だ。`
- `床がほのかに輝いている。`

強くしすぎないための制限:

- 追加アイテムは2個まで。
- 鉄の剣確定にはしない。
- 宝物部屋自体は1フロア最大1つ。

### 回復の泉

役割:

- 低HP時の救済。
- 自然回復とは違う、探索で見つける回復。
- HPを減らしてでも探索する理由を少し作る。

初期仕様:

- 部屋中央付近に泉オブジェクトを1つ置く。
- 泉のマスに乗ると1回だけ発動する。
- HPを最大HPの35%程度、最低8回復する。
- 満腹度は回復しない。
- 発動後は `used: true` にして、見た目を少し暗くする。
- 発動時にログ、SE、浮遊テキスト、薄い青緑フラッシュを出す。

回復量案:

```js
const healAmount = Math.max(8, Math.floor(state.player.maxHp * 0.35));
```

ログ案:

- 未使用で乗った時: `泉の水が吾郎をいやした。HP 12→20。`
- HP満タンで乗った時: `泉の水は静かに揺れている。`
- 使用済みで乗った時: `泉は静まり返っている。`

ターン扱い:

- 泉に乗る移動自体は通常移動なので1ターン経過する。
- 回復は `tickTurn()` の前に行う。
- 敵の攻撃を受ける可能性は残す。

## 見た目方針

### イベント部屋の照明

新しいタイル素材をいきなり増やさず、Canvas上のオーバーレイで表現する。

- 宝物部屋: 金色の薄い床光。
- 回復の泉: 青緑の薄い床光。

描画位置は `drawMapLayer()` の後、`drawStairsLayer()` の前が自然。新しい `drawEventRoomLayer()` を追加する。

### 回復の泉オブジェクト

最初はCanvas描画でよい。

- 1マス内に収まる小さな水面。
- 青緑の円形または楕円。
- 未使用時は淡く脈動。
- 使用済みは彩度と発光を落とす。

専用SVGは、見た目が固まってから追加する。

### 宝物部屋の追加アイテム

既存アイテムアイコンを使う。レア演出は、アイテム自体を強く光らせるのではなく、部屋の床光とログで伝える。

## 実装ステップ

### Step 1: イベント部屋基盤

目的:

特殊部屋を安全に生成、保持、判定できる土台を作る。

作業:

- `state.eventRooms` と `state.eventObjects` を追加する。
- `resetPlayerRunState()` と `generateFloor()` でイベント状態を初期化する。
- `floorEventTables` を追加する。
- `selectEventRooms(rooms)` を追加する。
- 開始部屋、階段部屋、小部屋を候補から除外する。
- イベント部屋の初回侵入判定を追加する。

完了条件:

- 低確率でイベント部屋が選ばれる。
- イベント部屋が開始位置や階段位置と重ならない。
- イベントなしフロアでも既存プレイが壊れない。

### Step 2: 宝物部屋

目的:

少量の追加報酬がある特殊部屋を作る。

作業:

完了条件:

- アイテムが重ならず拾得できる。

### Step 3: 回復の泉

目的:

探索中に1回だけ使える回復イベントを作る。

作業:

- `placeSpringObject(eventRoom)` を追加する。
- `eventObjectAt(x, y)` を追加する。
- `handleEventObjectAtPlayer()` を `tryMove()` の移動後に呼ぶ。
- 泉の回復量、ログ、SE、浮遊テキスト、フラッシュを追加する。
- 泉オブジェクトを描画する。
- 使用済みの見た目を追加する。

完了条件:

- 泉に乗るとHPが回復する。
- 1つの泉は1回だけ有効。
- HP満タン時や使用済み時のログが破綻しない。
- 回復後もターン進行と敵行動が成立する。

### Step 4: 生成バランスと衝突整理

目的:

イベントが既存の成長、敵配置、アイテム配置、階段移動を壊さないようにする。

- 敵やアイテムの配置数がイベント部屋で過密になりすぎないか確認する。
- 必要ならイベント部屋を通常敵配置候補から外す、または敵数を控えめにする。

完了条件:

## 受け入れ条件

- 通常部屋とは違う部屋が低確率で出る。
- 少なくとも宝物部屋と回復の泉が動く。
- 宝物部屋では追加アイテムが拾える。
- 回復の泉では1回だけHP回復できる。
- イベント発生時にログ、SE、見た目で分かる。
- イベント部屋、敵、アイテム、階段、開始位置が重なって破綻しない。
- イベントがゲームを壊すほど強すぎない。
- イベントなしフロアでも既存の探索、戦闘、拾得、階段移動が成立する。

## 確認方法

### 静的確認

- `node --check main.js`
- `rg eventRooms main.js`
- `rg eventObjects main.js`

### 生成確認

ブラウザ操作が難しい場合、スタブ環境または一時的なデバッグで複数階生成し、以下を確認する。

- イベント部屋が最大1つである。
- 開始部屋と階段部屋がイベント部屋にならない。
- 泉が壁、敵、階段、アイテムと重ならない。
- 宝物部屋の追加アイテムが壁、敵、階段、泉、既存アイテムと重ならない。
- イベントなしフロアが許容される。

### 手動確認

- 1Fで通常プレイが成立する。
- 宝物部屋に入るとログが出る。
- 宝物部屋の追加アイテムを拾える。
- 回復の泉の部屋に入るとログが出る。
- HPが減った状態で泉に乗ると回復する。
- HP満タンの時に泉へ乗っても不自然な回復ログにならない。
- 使用済みの泉に再度乗っても再回復しない。
- 泉回復後に敵ターンが進む。
- 階段移動後もイベント状態が前階から残らない。
- 全滅、リトライ後にイベント状態がリセットされる。

## リスクと対策

### リスク: `generateFloor()` がさらに大きくなる

対策:

- 抽選、配置、描画、発火を小さな関数に分ける。
- 既存の `placeEnemies()`、`placeItems()` と同じ粒度に揃える。

### リスク: 宝物部屋でアイテム供給が強すぎる

対策:

- 追加アイテムは2個までにする。
- 鉄の剣確定にしない。
- 出現率を階層ごとに低めから始める。

### リスク: 泉が薬草や自然回復の価値を奪う

対策:

- 泉は1回だけにする。
- 満腹度は回復しない。
- 回復量は最大HPの35%程度に抑える。
- 低確率出現にする。

### リスク: イベント部屋が見た目で分かりにくい

対策:

- タイル差だけに頼らず、部屋単位の淡い光を入れる。
- 初回侵入ログとSEを入れる。
- 泉は専用オブジェクトとして描く。

### リスク: 配置衝突が増える

対策:

- `isItemPlacementBlocked()` と同系統の判定にイベントオブジェクトを加える。
- イベント部屋候補を開始部屋、階段部屋から外す。
- 配置失敗時は無理に置かず、そのイベントをスキップする。
