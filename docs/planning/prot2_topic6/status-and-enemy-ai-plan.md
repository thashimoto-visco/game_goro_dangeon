# Topic 6 詳細プラン: 状態異常と敵AI

作成日: 2026-08-12

## 目的

Topic 6では、敵の違いを「HPと攻撃力の数値差」から「行動の違い」へ広げる。

同時に、その差を支える土台として、状態異常の仕組みを入れる。状態異常は毒から始め、毒が落ち着いてから眠りを足す。

最低ラインは、毒と眠りが動くこと、少なくとも2種類の敵が通常とは違う行動をすること、そして状態異常がUIとログで分かることとする。

## 速度を扱わない方針

行動頻度（倍速、鈍足）はTopic 6では扱わない。

倍速と鈍足は、1ターンあたりの行動回数を小数で持つ仕組みを必要とする。これはターンループの中心に手を入れることになり、既存の攻撃演出、`skipEnemy`、特殊遭遇の部屋制限と全部が絡む。状態異常の導入と同時にやると、不具合が出た時にどちらが原因か切り分けられない。

代わりに眠りを入れる。眠りは「そのターン行動するかしないか」の二択であり、行動回数を変えない。既存のターンループへ条件分岐を1つ足すだけで済む。得られる遊びの幅は倍速や鈍足と近く、実装の危険度はずっと低い。

倍速敵と鈍足はバックログへ残す。`mid-term-backlog.md` の `敵 / 倍速敵` と `戦闘 / 状態異常: 鈍足` が該当する。

## 現状理解

- 敵の行動は `moveEnemies()` の1関数にすべて入っている。プレイヤーへ向かうX方向とY方向を求め、それぞれ50%の確率で1マス動く。プレイヤーのマスへ入ろうとしたら攻撃になる。
- 敵は1プレイヤーターンにつき必ず1回だけ行動する。この前提はTopic 6でも変えない。
- 敵の差はカタログの `stats`（baseHp / baseAtk / hpScale / atkScale / exp）だけで、行動は全種共通である。
- ターン進行は `tickTurn()` に集約されている。順序は、ターン数加算、満腹度減少、空腹ダメージ、自然回復、敵の行動である。
- プレイヤーの攻撃は `state.action` を使った演出付きの遅延処理で、決着後の `finishAction()` が `tickTurn({ skipEnemy })` を呼ぶ。攻撃された敵はそのターン行動しない。
- 敵へダメージを与える処理が3箇所に分かれている。`applyPlayerAttackHit()`、`resolveThrownHit()`、`applyThunderScroll()` で、`hitTime` の設定、バースト演出、浮遊テキスト、撃破判定をそれぞれ書いている。
- 特殊遭遇の敵は `specialEncounterSystem.containsPosition()` により割り当てられた部屋の外へ出ない。
- 敵の状態はプレーンなオブジェクトで、`hp` / `atk` / `tags` / `encounterRank` / `spotted` / `hitTime` などを持つ。状態異常に相当するフィールドはない。
- Topic 5で `tags`（`slime` / `beast` / `stone` / `demon`）が入り、悪魔斬りの剣の特効判定に使われている。耐性判定にも流用できる。
- Topic 5で「カタログ（データ）＋システム（挙動）＋テーブル（配分）」の三層構成が確立した。`monster-*`、`item-*`、`dungeon-item-tables.js` が同じ形になっている。
- Topic 5で `throwPathTiles()` という直線経路の走査があり、方向指定の効果に流用できる。
- 敵の頭上には残HPバーがあり、強敵にはオーラがある。状態異常マークを足す余地はここにある。
- HTML側のステータス欄は `index.html` の `<dl>` にあり、行を1つ足すだけで増やせる。
- ログは12行で流れる。毎ターン出るログを足すと、他の情報が読めなくなる。
- 全滅時の死因は `defeatReasons` にあり、空腹用の文言がすでにある。

## スコープ

- 状態異常のカタログとシステムを新設する。プレイヤーと敵の両方へ同じ仕組みで付与できるようにする。
- 状態異常「毒」を実装する。
- 状態異常「眠り」を実装する。
- 敵へのダメージ処理を1箇所へまとめる。
- 敵AIの共通インターフェースを新設し、既存の追跡行動をその上へ移す。
- 遠距離攻撃を行う敵AIを追加する。
- 毒を付与してくる近接敵を追加する。
- 状態異常のUI表示（プレイヤーのステータス欄、敵の頭上マーク、浮遊テキスト）を追加する。
- 状態異常を治すアイテムを追加する。
- アイテム種別「杖」を追加し、敵を眠らせる杖を実装する。
- 状態異常システムと敵AIのユニットテストを追加する。
- README、手動テストチェックリスト、ロードマップ、完了メモを更新する。

## 非スコープ

- 倍速敵、鈍足、行動頻度の変更。上の「速度を扱わない方針」の通り。
- 混乱、麻痺。
- プレイヤーが眠る状態。理由は後述する。
- アイテムを盗む敵。持ち物からの削除と、敵が持ち物を抱えて逃げる挙動が必要で、範囲が広い。
- 壁抜け敵。移動可能判定と視界計算の前提を崩す。
- 敵から敵への状態異常伝播。
- 属性システム、耐性の数値化。耐性はタグによる完全無効のみとする。
- 眠っている敵への追加ダメージ倍率。
- 敵の予備動作、詠唱、行動予告。
- ボス、複数体で連携する敵。
- 経路探索。追跡は現在の単純な方式を保つ。

## 目標体験

- どくトカゲに殴られた後、毒が残っていることに気付き、進むか薬草を使うか迷う。
- 毒の間はHPが自然に戻らないので、階段を急ぐか一度立て直すかを考える。
- 毒のまま歩き続けて倒れかけ、次からはなおし草を温存するようになる。
- ぷくぷくキノコに遠くから撃たれて、間合いを詰めるまでに削られる。
- 物陰に入れば撃たれないと気付き、近づき方を考える。
- 眠りの杖で強敵を止め、殴るか通り過ぎるかを選べる。
- 眠っている敵を殴ると起きるので、一方的に倒しきれるわけではないと分かる。
- 状態異常が付いた時と切れた時が、ログとステータス欄で必ず分かる。
- 毒は痛いが、8ターン我慢すれば切れると分かる。

## 実装方針

### 全体の並び

Topic 5と同じ三層構成へそろえる。

- `status-catalog.js`: 状態異常の定義（データのみ）。
- `status-system.js`: 付与、経過、失効、解除の判定。HPやログには触らない。
- `monster-ai.js`: 敵の行動決定。座標と判定関数だけを受け取り、実行はしない。

3つとも `main.js` から切り離し、DOMもCanvasも使わない。Nodeの `vm` でそのままテストできる形にする。

### 状態異常の持ち方

プレイヤーも敵も、同じ形の配列を持つ。

```js
actor.statuses = [
  { key: "poison", remaining: 8 },
];
```

`status-catalog.js` の1件はこの形にする。

```js
{
  key: "poison",
  name: "毒",
  mark: "毒",
  color: "#a3e635",
  duration: 8,
  tickDamage: 1,
  blocksAction: false,
  blocksNaturalRecovery: true,
  clearedByDamage: false,
  resistTags: ["stone"],
  messages: {
    apply: "{name}は毒を受けた！",
    expire: "{name}の毒が消えた。",
  },
}
```

```js
{
  key: "sleep",
  name: "眠り",
  mark: "Zzz",
  color: "#c4b5fd",
  duration: 5,
  tickDamage: 0,
  blocksAction: true,
  blocksNaturalRecovery: false,
  clearedByDamage: true,
  resistTags: [],
  messages: {
    apply: "{name}は眠ってしまった。",
    expire: "{name}が目を覚ました。",
    cleared: "{name}は衝撃で目を覚ました！",
  },
}
```

`resistTags` はTopic 5で入れた敵タグを使う。ゴーレムは `stone` を持つので毒が効かない。敵カタログ側を書き換えずに耐性を表現できる。

`clearedByDamage` はデータで持つ。眠り専用の分岐をコードへ書かないためである。将来「ダメージで解けない眠り」を作りたくなっても、カタログ側で表現できる。

### 状態異常システムのAPI

`status-system.js` は状態を計算するだけで、ダメージ適用もログ出力もしない。呼び出し側が結果を見て処理する。この分け方はTopic 5の `item-system.js` と同じで、テストしやすさのためである。

```js
statusSystem.apply(actor, "poison", { tags: actor.tags });
// → { applied: true, refreshed: false } / { applied: false, reason: "resist" }

statusSystem.tick(actor);
// → [{ key: "poison", damage: 1, expired: false },
//    { key: "sleep",  damage: 0, expired: true }]

statusSystem.onDamage(actor);
// → 解除された状態異常の配列。眠りの覚醒はここで起きる。

statusSystem.blocksAction(actor);           // 眠っているか
statusSystem.blocksNaturalRecovery(actor);  // 毒を受けているか
statusSystem.has(actor, "sleep");
statusSystem.clearAll(actor);               // 治療アイテム用
statusSystem.marks(actor);                  // UI用の [{ mark, color, remaining }]
```

同じ状態異常を重ねて受けた場合は、強度を上げず残りターン数を長い方で上書きする。重ねがけで即死する事故を防ぐためである。

### 敵へのダメージ処理の共通化

眠りを「ダメージで起きる」ようにするには、敵がダメージを受ける場所が1箇所である必要がある。現在は3箇所に分かれているため、先にまとめる。

```js
function damageEnemy(enemy, amount, options = {}) {
  enemy.hp -= amount;
  enemy.hitTime = 180;
  enemy.hitDuration = 180;
  enemy.hitDirection = options.direction || directionBetween(state.player, enemy);
  addMonsterBurstEffect(enemy, "hit");
  addImpactEffect(enemy.x, enemy.y);
  addFloatingText(String(amount), enemy.x, enemy.y, options.color || "#fde68a");

  for (const cleared of statusSystem.onDamage(enemy)) {
    addLog(statusMessage(cleared, "cleared", enemy.name));
  }

  if (enemy.hp <= 0) handleEnemyDefeat(enemy);
}
```

`applyPlayerAttackHit()`、`resolveThrownHit()`、`applyThunderScroll()` の3箇所をこれに置き換える。眠りとは関係なく、重複していた処理が減る。

この共通化は眠りを入れる直前の手順に置く。先にやると意味が分かりにくく、後にやると眠りの覚醒を3箇所に書くことになる。

### ターン進行への組み込み

`tickTurn()` の順序を次のようにする。

1. ターン数加算。
2. 満腹度減少と空腹ダメージ。
3. プレイヤーの状態異常を経過させる。毒ダメージを適用する。ここで倒れたら毒用の死因で全滅にする。
4. 自然回復。毒を受けている間は行わない。
5. 敵の行動。

敵側は、行動する直前に自分の状態異常を経過させる。眠っていれば行動しない。

```js
for (const enemy of state.enemies) {
  if (enemy.hp <= 0) continue;
  if (options.skipEnemy === enemy) continue;

  applyEnemyStatusTick(enemy);
  if (enemy.hp <= 0) continue;
  if (statusSystem.blocksAction(enemy)) continue;

  performEnemyIntent(enemy);
}
```

眠りを与えた直後のターンにも経過処理が走るので、残り5ターンの眠りは実際には5回の行動を止める。杖を振るのに1ターン使うため、差し引き4ターン分の得になる。

全滅時の死因に毒用の文言を足す。

```js
const defeatReasons = {
  hunger: "吾郎は空腹で倒れた",
  poison: "吾郎は毒に倒れた",
  fallbackEnemy: "吾郎は力尽きた",
};
```

### 敵AIの共通インターフェース

AIは「何をしたいか」を返すだけにする。移動もダメージも `main.js` 側が実行する。

```js
// monster-ai.js
behavior.decide(enemy, context) -> intent
```

`context` に渡すのは、座標と判定関数だけにする。

```js
{
  player: { x, y },
  isWalkable(x, y),
  enemyAt(x, y),
  isBlockedForEnemy(x, y),          // 特殊遭遇の部屋制限を含む
  straightPathTo(from, to, range),  // 直線上に障害物がなければタイル配列、なければnull
  rng,
}
```

返す `intent` は4種類に絞る。

```js
{ type: "wait" }
{ type: "move", x, y }
{ type: "melee" }
{ type: "ranged", path }
```

MVPで用意する行動は2つ。

- `chase`: 現在の `moveEnemies()` と同じ判断を、そのまま移したもの。既定値。
- `ranged`: 直線上にプレイヤーがいて射程内なら撃つ。隣接している場合は1マス離れる。射線が通らない、または射程外なら追う。

`chase` を先に切り出し、既存の敵の動きが1マスも変わらないことを確認してから `ranged` を足す。土台の差し替えと新機能追加を分けるのは、Topic 5と同じ理由である。

毒付与はAIではなく、攻撃時の属性として扱う。AIに混ぜると、行動の種類とパラメータの区別が崩れる。

### 攻撃時の状態異常付与

敵カタログに攻撃属性として持たせる。近接も遠距離も同じ処理を通す。

```js
onHitStatus: { key: "poison", chance: 30 },
```

プレイヤーがダメージを受けた後に判定する。耐性で弾かれた場合はログを出さない。

### 追加する敵

| キー | 表示名 | 役割 | AI | 攻撃属性 | 出現 |
| --- | --- | --- | --- | --- | --- |
| `poisonLizard` | どくトカゲ | 毒の導入 | `chase` | 毒30% | 3F〜 |
| `puffMushroom` | ぷくぷくキノコ | 遠距離の導入 | `ranged` | なし | 4F〜 |

ぷくぷくキノコは射程4マス、HPは低め、遠距離攻撃力は近接敵よりやや低くする。近づけば倒せるが、近づくまでに削られる形にする。

どちらも既存3敵より後の階層から出し、1Fから2Fの体感は変えない。

### 追加するアイテム

Topic 5の完了メモに書いた通り、既存の器へ足すだけで済む。

| キー | 表示名 | 種別 | 効果 |
| --- | --- | --- | --- |
| `cureHerb` | なおし草 | 薬 | 状態異常をすべて治す |
| `sleepWand` | 眠りの杖 | 杖 | 直線上の敵1体を眠らせる |

なおし草は既存の `potion` 種別をそのまま使う。`item-system.js` の変更はいらない。「毒消し」ではなく「すべて治す」にするのは、状態異常が増えるたびに専用の治療アイテムを足さずに済むようにするためである。

杖は新種別なので、`KIND_PROFILES` へ1件足す。

```js
wand: { label: "杖", actionLabel: "振る", equipSlot: null, upgradable: false, consumable: false, throwPower: 3 },
```

杖は使い切りではなく残り回数を持つ。Topic 5で `upgrade` を個体フィールドにした前例があるので、同じ形で `uses` を足す。

- 表示名は `眠りの杖[3]` の形にする。
- 残り0で振ると空振りのログを出す。消滅はさせない。床に落ちている杖も残り回数を保つ。
- 方向指定は `throwPathTiles()` をそのまま使う。射程は投擲と同じ6マス。

### プレイヤーが眠らない理由

眠りはプレイヤーにも技術的には付与できるが、MVPでは誰も付与しない。

数ターン操作を奪われる状態異常は、隣に敵がいるかどうかで理不尽さが大きく変わる。毒のように「痛いが自分で対処できる」ものと違い、眠っている間は何もできない。まず敵に付ける側で挙動と表示を確かめてから、プレイヤー側へ広げたい。

システムは対称に作るので、眠らせてくる敵を足したくなった時は、敵カタログへ `onHitStatus: { key: "sleep", chance: 15 }` を書くだけで済む。

### UIとログ

状態異常が増えると、ログが埋まりやすい。表示の役割を分ける。

- ステータス欄: 常時の確認用。`状態` 行を足し、`毒(6)` のように残りターンまで出す。何もなければ `なし`。
- 敵の頭上: 残HPバーの上に、状態異常の色付きマークを並べる。眠りは `Zzz`。
- 浮遊テキスト: 付与された瞬間と、毒ダメージが入った瞬間。
- ログ: 付与、失効、ダメージによる解除のときだけ出す。毒ダメージは毎ターン出さない。

毒ダメージをログに出さない理由は、8ターン続く状態異常が12行のログを1人で埋めてしまうためである。ダメージが入ったことは浮遊テキストとHP表示で分かる。

眠っている敵は、待機アニメーションの揺れを止めるか遅くする。マークだけでなく動きでも分かるようにする。

### バランスの初期値

理不尽にしないことを優先し、以下から始める。

- 毒: 1ターン1ダメージ、8ターン。合計8ダメージ。レベル1の最大HP20に対して痛いが、満タンからは死なない。
- 毒の間は自然回復しない。毒の重さを数値ではなく「立て直せない」で表現する。
- 毒の付与率30%。どくトカゲは3Fから。
- ゴーレムは毒が効かない。`stone` タグによる。
- 眠り: 5ターン。ダメージで起きる。
- 眠りの杖は残り3回。強敵を止められるが、何度も止め続けることはできない。
- 状態異常は階層をまたいでも消えない。残りが短いので、階段で解除できると意味がなくなる。リトライでは消す。

数値はすべて `status-catalog.js` と `monster-catalog.js` にあり、コードを触らずに調整できる。

手順5と手順7は、見た目の変化が一切ないことが正しい状態である。土台の差し替えでバグが出たのか、新しい要素の追加でバグが出たのかを切り分けられるようにするためである。

毒を手順4まででいったん完成させてから眠りへ進むのは、状態異常の表示とログの作法を、追加のたびに作り直さないためである。

## テスト方針

### `tests/status-system-tests.js`

- 付与すると残りターンが設定される。
- 同じ状態異常の再付与で、残りターンが長い方になる。強度は上がらない。
- `resistTags` に一致するタグを持つ相手には付かない。
- `tick()` が残りターンを1減らし、0で失効を返す。
- `tick()` が `tickDamage` を返すが、HPには触らない。
- `blocksAction()` が眠りで真、毒で偽になる。
- `blocksNaturalRecovery()` が毒で真、眠りで偽になる。
- `onDamage()` が `clearedByDamage` の状態異常だけを解除する。毒は残る。
- `clearAll()` で空になる。
- 状態異常を持たない相手に対して、すべてのAPIが安全に動く。

### `tests/monster-ai-tests.js`

- `chase` が、現在の `moveEnemies()` と同じ判断を返す（隣接時は `melee`、離れていれば `move`）。
- `chase` が壁と他の敵を避ける。
- `chase` が特殊遭遇の部屋制限を越えない。
- `ranged` が、直線上かつ射程内なら `ranged` を返す。
- `ranged` が、射線に壁がある場合は撃たない。
- `ranged` が、隣接時は距離を取る。
- `ranged` が、射程外なら近づく。
- 未知のAIキーが `chase` へフォールバックする。

### 既存テスト

`structure-tests.js`、`monster-system-tests.js`、`special-encounter-tests.js`、`item-system-tests.js` がすべて通ること。特に `monster-system-tests.js` の既存3敵の生成値が変わっていないことを確認する。

### 実機に近い確認

Topic 5で使ったDOM差し替えの起動確認を再利用し、以下を実測する。

- 毒を受けてから8ターンで切れる。
- 毒の間は自然回復しない。
- 毒でHPが0になると毒用の死因が出る。
- ゴーレムに毒が付かない。
- なおし草で状態異常が消える。
- 遠距離敵が射線の通る位置からだけ撃つ。
- 遠距離敵が隣接時に離れる。
- 眠らせた敵が5ターン行動しない。
- 眠っている敵を殴ると起きる。
- 眠りの杖の残り回数が減り、0で空振りになる。
- 階段を降りても状態異常が残り、リトライで消える。
- ランダム操作の連続実行で例外が出ない。

## 受け入れ条件

ロードマップの条件:

- 少なくとも2種類の敵が特殊行動を持つ。
- 状態異常はUIとログで分かる。
- 状態異常が理不尽すぎない。

本プランで足す条件:

- 毒と眠りが、同じ仕組みでプレイヤーと敵の両方へ付与できる形になっている。
- 状態異常の残りターンがステータス欄で分かる。
- 敵に付いた状態異常が頭上のマークで分かる。
- 毒の間は自然回復しない。
- 石タグを持つ敵に毒が効かない。
- 眠っている敵がダメージで起きる。
- 敵へのダメージ処理が1箇所にまとまっている。
- 敵AIを1つ足す時に、`main.js` の変更が不要である。
- 状態異常を追加する時に、`status-catalog.js` へ1件足すだけで済む。
- 既存の1Fから2Fの体感が変わっていない。
- 既存4テストと新規2テストが通る。

## 残す判断

- 倍速と鈍足は入れない。ターンループの中心を小数の行動回数で作り直すことになり、状態異常の導入と同時にやると原因の切り分けができない。バックログへ残す。
- 混乱と麻痺は入れない。眠りで「操作や行動を止める」系の作法を確かめてから考える。
- プレイヤーが眠る状態は入れない。まず敵側で挙動と表示を確かめる。
- 眠っている敵への追加ダメージ倍率は入れない。倍率を入れると、眠りが足止めではなく処刑手段になり、杖の残り回数の設計が変わる。
- アイテムを盗む敵と壁抜け敵はTopic 7以降へ回す。前者は持ち物の整合、後者は移動と視界の前提に触るため、状態異常と同時にやると原因の切り分けが難しくなる。
- 経路探索は入れない。現在の単純な追跡でも、遠距離敵が入れば行動の差は十分に出る。
- 耐性はタグによる完全無効だけにする。確率軽減や耐性値は、敵の種類が増えてから考える。
- 遠距離攻撃の弾は、敵が撃った瞬間に着弾させる。飛翔中に割り込める仕様にすると、ターンの区切りが複雑になる。
- 状態異常は階層をまたいで残す。短いので、階段での解除を認めると存在意義が薄れる。
- 毒ダメージはログに出さない。12行のログを1つの状態異常で埋めないためである。

## 次Topicへの引継ぎ候補

- Topic 7のマップ生成強化で罠を実装する際、状態異常をそのまま付与元として流用できる。
- 混乱と麻痺は `status-catalog.js` へ1件ずつ足す形で追加できる。ただし、操作を奪う状態異常はUIでの分かりやすさを別途設計する。
- 眠らせてくる敵は、敵カタログへ `onHitStatus: { key: "sleep", chance: 15 }` を書くだけで足せる。
- 状態異常を与える武器（毒の剣など）は、Topic 5の `slayer` と同じ形で武器定義へフィールドを足せる。
- 倍速と鈍足を将来入れる場合、`performEnemyIntent()` の呼び出し回数だけを変える形になる。AIとダメージ処理には触らずに済むよう、今回の分離を保つ。
- 敵の予備動作は、`intent` に「次に何をするか」を持たせる形で拡張できる。
- ボスを作る場合、`monster-ai.js` へ複数の行動を切り替えるAIを1つ足す形になる。
