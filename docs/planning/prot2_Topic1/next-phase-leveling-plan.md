# Topic 1 詳細プラン: ローグライク基礎の完成度向上

## 目的

Topic 1では、現状の「移動、戦闘、持ち物、階段、全滅まで遊べる骨格」を、数階層ぶん納得して遊べるローグライク基礎へ引き上げる。

中心はレベル、経験値、敵/アイテム出現テーブル、1Fから5F程度までの難度カーブである。強敵、イベント、追加アイテムへ進む前に、敵を倒す意味と階層を進む緊張感を成立させる。

## 現状

- 隣接敵方向への移動入力で通常攻撃できる。
- 敵撃破時に経験値が増えるが、現在は固定値加算でレベルアップはない。
- UIには経験値が表示されているが、レベルや次レベルまでの情報はない。
- 敵は3種類あり、階層に応じてHP/攻撃がスケールする。
- 敵出現は部屋順にモンスター種別を循環させる形で、階層ごとの出現テーブルはない。
- アイテムは単一の出現テーブルから抽選される。
- 満腹度は毎ターン減り、0になると空腹ダメージを受ける。
- HP自然回復はまだない。

## スコープ

- プレイヤーレベルを追加。
- 経験値テーブルを追加。
- 敵ごとの獲得経験値を追加。
- レベルアップ時の最大HP、攻撃、守備上昇を追加。
- レベルアップ時のログ、SE、簡易演出を追加。
- UIにレベル、経験値、次レベルまでを表示。
- HP自然回復の導入方針を決め、必要最小限で実装。
- 満腹度と自然回復の関係を整理。
- 階層ごとの敵出現テーブルを追加。
- 階層ごとのアイテム出現テーブルを追加。
- 1Fから5F程度までの難度カーブを調整。
- READMEと手動テスト項目を更新。

## 非スコープ

- 新しい敵種の大量追加。
- 強敵、ボス、レアモンスター。
- 状態異常、特殊AI。
- 盾、防具、巻物、杖などの大幅なアイテム拡張。
- 視界制限、未識別、呪いなどの本格ローグライク要素。
- 大規模なファイル分割。
- 自動バランスシミュレーター。

## 目標体験

- 1Fでは安全に操作、戦闘、拾得、階段移動を確認できる。
- 2Fから3Fでは敵撃破でレベルアップし、成長が体感できる。
- 4Fから5Fではレベル、装備、回復アイテムの状況によって危険度が変わる。
- 敵を倒すか避けるかの判断が、経験値とHP消耗のトレードオフとして成立する。
- 満腹度が高い時は軽い自然回復があり、足踏みや探索に意味が出る。
- 満腹度が低い時は回復が止まり、食料の価値が分かる。

## データ設計

### プレイヤー成長

`state.player` に以下を追加する。

```js
level: 1,
exp: 0,
nextExp: 8,
```

`nextExp` は表示用に保持してもよいが、実体は経験値テーブルから計算できるため、関数化してもよい。

初期候補:

```js
const levelTable = [
  { level: 1, nextExp: 8, maxHp: 20, atk: 5, def: 2 },
  { level: 2, nextExp: 20, maxHp: 24, atk: 6, def: 2 },
  { level: 3, nextExp: 38, maxHp: 29, atk: 7, def: 3 },
  { level: 4, nextExp: 62, maxHp: 34, atk: 8, def: 3 },
  { level: 5, nextExp: 92, maxHp: 40, atk: 9, def: 4 },
  { level: 6, nextExp: 128, maxHp: 46, atk: 10, def: 4 },
];
```

Topic 1では5F程度までを対象にするため、レベル6まであれば十分。経験値が上限を超えた場合は、最大レベル扱いで「次: --」の表示にする。

### レベルアップ処理

敵撃破時に `gainExp(enemy.exp)` を呼ぶ。

方針:

- 獲得経験値をログに出す。
- 必要経験値を超えていれば連続レベルアップを許可する。
- レベルアップ時は最大HP、攻撃、守備をテーブル値へ更新する。
- 最大HP上昇ぶんは現在HPにも加算する。
- HPは新しい最大HPを超えない。
- レベルアップ時にログ、浮遊テキスト、短いフラッシュ、SEを出す。

ログ候補:

- `ぬるりスライムをたおした！ 経験値を4得た。`
- `吾郎はレベル2になった！`
- `最大HP 20→24 / 攻撃 5→6`

### 敵ごとの経験値

既存の `monsterTypes` に `exp` を追加する。

初期候補:

```js
const monsterTypes = {
  slime: { key: "slime", name: "ぬるりスライム", baseHp: 5, baseAtk: 2, hpScale: 1.0, atkScale: 0.35, exp: 4 },
  bat: { key: "bat", name: "バサバサコウモリ", baseHp: 4, baseAtk: 3, hpScale: 0.8, atkScale: 0.45, exp: 5 },
  golem: { key: "golem", name: "ゴロ岩ゴーレム", baseHp: 9, baseAtk: 4, hpScale: 1.4, atkScale: 0.6, exp: 9 },
};
```

現在の配列形式でも実装できるが、階層テーブルから参照するならキー指定しやすいオブジェクト形式が扱いやすい。

## HP自然回復

### 導入方針

Topic 1では自然回復を入れる。ただし強くしすぎず、満腹度と結びつける。

候補:

- 満腹度が70以上: 8ターンごとにHP+1。
- 満腹度が30から69: 12ターンごとにHP+1。
- 満腹度が1から29: 自然回復なし。
- 満腹度が0: 空腹ダメージのみ。

理由:

- 満腹度が高い時は足踏み回復の余地がある。
- 食料が自然回復の燃料として意味を持つ。
- 低満腹時に無限回復できない。
- 回復薬の価値を消しすぎない。

実装候補:

```js
recoveryCounter: 0,
```

`tickTurn()` 内で満腹度減少後、HPが最大未満なら回復判定を行う。空腹ダメージが発生したターンは自然回復しない。

### Space足踏みとの関係

足踏みは1ターン経過として扱う。自然回復も発生する。ただし敵も動くため、安全な場所でのみ有効になる。

## 階層ごとの敵出現テーブル

### 方針

階層ごとに敵の出現比率と出現数を定義する。

初期候補:

```js
const floorEnemyTables = [
  { minFloor: 1, maxFloor: 1, count: [3, 4], entries: [{ type: "slime", weight: 100 }] },
  { minFloor: 2, maxFloor: 2, count: [4, 5], entries: [{ type: "slime", weight: 75 }, { type: "bat", weight: 25 }] },
  { minFloor: 3, maxFloor: 3, count: [4, 5], entries: [{ type: "slime", weight: 50 }, { type: "bat", weight: 40 }, { type: "golem", weight: 10 }] },
  { minFloor: 4, maxFloor: 4, count: [5, 6], entries: [{ type: "slime", weight: 35 }, { type: "bat", weight: 45 }, { type: "golem", weight: 20 }] },
  { minFloor: 5, maxFloor: 99, count: [5, 7], entries: [{ type: "slime", weight: 20 }, { type: "bat", weight: 45 }, { type: "golem", weight: 35 }] },
];
```

1Fはスライム中心、2Fからコウモリ、3F以降にゴーレムを混ぜる。5F以降は暫定的に同じテーブルでよい。

### 生成ルール

- 開始部屋には敵を置かない。
- 階段と同じ位置には置かない。
- 敵同士を重ねない。
- 部屋数が足りない場合は部屋内ランダム座標へ置く。
- 生成失敗時は無理に詰め込まず、上限試行回数で止める。

### 方針

序盤は回復と食料を厚めにし、深い階ほど武器の価値を少し上げる。

初期候補:

```js
    { type: "riceBall", weight: 32 },
    { type: "herb", weight: 34 },
    { type: "woodenSword", weight: 24 },
    { type: "ironSword", weight: 10 },
  ] },
  { minFloor: 4, maxFloor: 99, count: [3, 6], entries: [
    { type: "riceBall", weight: 30 },
    { type: "herb", weight: 30 },
    { type: "woodenSword", weight: 22 },
    { type: "ironSword", weight: 18 },

```

Topic 1では新規アイテムを増やさず、既存アイテムの出現率だけで難度を調整する。

## 1Fから5Fの難度カーブ

### 目標

- 1F: 操作確認。ほぼ死なない。
- 2F: レベル2到達が見える。
- 3F: 装備なしでも進めるが、HP管理が必要。
- 4F: ゴーレムや複数敵で危険が出る。
- 5F: レベル3から4、武器、回復薬の有無で突破率が変わる。

### 期待値

- 1F終了時: レベル1から2手前、またはレベル2。
- 2F終了時: レベル2。
- 3F終了時: レベル2から3。
- 5F到達時: レベル3前後。

経験値が入りすぎる場合は敵経験値を下げる。全滅が早すぎる場合は、敵攻撃の階層スケールか自然回復間隔を調整する。

## UI方針

現在のステータス欄に以下を追加または差し替える。

- `レベル`: `1`
- `経験値`: `4 / 8`
- `次Lv`: `あと4`

スペースに余裕がなければ、経験値行を `経験値 4 / 8` のようにまとめ、次Lv行は省略してよい。

全滅時の戦績にもレベルを追加する。

表示候補:

- `レベル: 3`
- `経験値: 31`
- `撃破数: 12`

## 音と演出

レベルアップは、既存のWeb Audio方針に合わせて外部アセットなしで実装する。

- 短い上昇ジングル。
- プレイヤー位置に `Lv UP` の浮遊テキスト。
- 画面全体に薄い金色フラッシュ。
- ログに成長内容を表示。

攻撃や撃破演出より長くしすぎない。入力停止は既存攻撃アクションの範囲内に留め、レベルアップだけでテンポを止めない。

## 受け入れ条件

- 敵を倒すと、敵ごとに異なる経験値を得る。
- 経験値がしきい値を超えるとレベルアップする。
- レベルアップで最大HP、攻撃、守備のいずれかが上がる。
- レベルアップ時にログ、浮遊テキスト、SEまたは視覚演出が出る。
- UIにレベル、経験値、次レベルまでの情報が表示される。
- 満腹度が十分ある時だけHP自然回復が発生する。
- 満腹度が低い時、または0の時に自然回復しない。
- 1Fから5F程度まで、敵とアイテムの出現傾向が階層ごとに変わる。
- 1Fから数階層を遊んで、即死でも退屈でもない。
- 全滅後に今回の到達レベルが分かる。

## 手動テスト

### レベルと経験値

- 1Fで敵を倒す。
- 経験値表示が増える。
- ログに獲得経験値が出る。
- 必要経験値に達するとレベルアップする。
- レベルアップ後、HP最大値や攻撃値が増える。
- 複数レベルぶんの経験値を得た場合でも処理が破綻しない。

### UI

- 起動直後にレベル1、経験値0が表示される。
- レベルアップ後に表示が更新される。
- 最大レベル到達時の次レベル表示が不自然でない。
- 全滅画面にレベルが表示される。
- リトライ時にレベル、経験値、HP、攻撃、守備が初期化される。

### 自然回復

- HPを減らした状態で満腹度70以上にする。
- 数ターン経過でHPが1回復する。
- 満腹度30から69でも、より遅い間隔で回復する。
- 満腹度29以下では回復しない。
- 満腹度0では空腹ダメージが優先される。
- HP最大時は自然回復ログが過剰に出ない。

### 階層テーブル

- 1Fではスライム中心になる。
- 2F以降にコウモリが混ざる。
- 3F以降にゴーレムが低確率で出る。
- 4Fから5Fで敵数が少し増える。
- アイテムが階段、敵、プレイヤーと重ならない。
- 1Fから5Fまで階段移動しても生成が破綻しない。

### 難度確認

- 1Fで理不尽に倒されない。
- 2Fから3Fでレベルアップを体験できる。
- 4Fから5FでHP、食料、回復薬の管理が必要になる。
- 武器を拾えた時に敵撃破が楽になる。
- 回復薬や食料が少ない時に撤退判断、敵回避判断が生まれる。

## リスクと対策

### リスク: レベルアップで簡単になりすぎる

対策:

- 攻撃上昇を毎レベルではなく、テーブルで抑える。
- 敵HPの階層スケールを少し上げる。
- 自然回復間隔を長くする。

### リスク: 自然回復で足踏みが強すぎる

対策:

- 満腹度70以上でも8ターンに1回程度に抑える。
- 満腹度消費を現状通り維持する。
- 敵が近い場合は足踏みが危険になるため、敵行動は止めない。

### リスク: 経験値テーブルと敵出現が噛み合わない

対策:

- まず5Fまでの手動プレイを基準にする。
- 1Fから3Fのレベル到達期待値を優先して調整する。
- 敵経験値、敵数、敵攻撃力を一度に大きく変えない。

### リスク: UI欄が詰まる

対策:

- 経験値を `現在 / 次` の1行にまとめる。
- 次レベルまで表示は必要なら省略する。
- ステータス欄の見出しを短くする。

### リスク: `main.js` の責務が増える

対策:

- Topic 1では単一ファイル維持でよい。
- 成長、敵テーブル、アイテムテーブルは定数と小さな関数に分ける。
- Topic 2以降で必要になった時に分割を検討する。
