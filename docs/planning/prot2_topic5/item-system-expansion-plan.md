# Topic 5 詳細プラン: アイテム体系の拡張

作成日: 2026-08-05

## 目的

Topic 5では、武器、食料、回復薬の3種別しかない現状に、「攻撃力以外で迷う」判断材料を足す。

種類を一気に増やすのではなく、まず種別を増やしても壊れない土台を作り、その上に最小限の新種別を載せる。最低ラインは、盾で守備が変わること、巻物で装備が育つこと、持ち物メニューが種別ごとに破綻せず操作できることとする。

## 現状理解

- アイテム定義は `main.js` の `itemTypes` にオブジェクトリテラルで直書きされている。
- 種別は `kind` が `weapon` / `food` / `potion` の3つだけで、`useInventorySlot()` の if 分岐に直接対応している。
- 装備スロットは `state.player.weapon` の1本だけで、武器IDを直接持っている。
- 守備は `state.player.def` のみで、レベルアップ以外に変化しない。
- 床アイテムと持ち物は `{ id, type }`（床は `+ x, y`）で、個体差を持てない。
- 階層別アイテム表 `floorItemTables` と宝物部屋表 `treasureRewardTables` は `main.js` 内にある。敵側は `dungeon-spawn-tables.js` に分離済みで、非対称になっている。
- 強敵の確定報酬は `dungeon-encounter-tables.js` の `rewardProfiles.strongDefault` にある。
- 満腹度は上限100が `Math.min(100, ...)` としてコード内に固定されている。
- 持ち物メニューは `drawInventoryMenu()` にあり、`Enter`（使う/装備）、`D`（置く）、`Esc` のみ。
- 説明文は `itemTypes[].description` の1行だけで、効果値と二重管理になっている。
- モンスターは `monster-catalog.js`（データ）と `monster-system.js`（挙動）に分離済みで、これがこのリポジトリの標準的な分け方になっている。

## スコープ

- アイテムのデータと挙動を `item-catalog.js` / `item-system.js` へ分離する。
- 階層別アイテム表を `dungeon-item-tables.js` へ分離する。
- 装備スロットを武器と盾の2枠へ拡張する。
- 盾の守備補正を被ダメージ計算へ反映する。
- 装備の強化値（`+N`）を導入する。
- 巻物種別と、強化の巻物、いかずちの巻物を追加する。
- 持ち物からの「投げる」操作と飛び道具演出を追加する。
- 満腹度の最大値を状態として持ち、最大値を上げる食料を追加する。
- モンスターのタグと、タグに対する特効を持つレア武器を追加する。
- 種別ラベル、効果文、フレーバー文の2段構成へ説明表示を拡充する。
- 新種別のアイコン、床上のフォールバック形状、淡い光の色を追加する。
- 出現テーブル、宝物部屋、強敵報酬へ新アイテムを配分する。
- アイテムシステムのユニットテストを追加する。
- README、手動テストチェックリスト、ロードマップ、完了メモを更新する。

## 非スコープ

- 状態異常そのものと、状態異常回復薬。Topic 6で状態異常を入れてから追加する。
- 杖。振る対象の指定や効果は状態異常と一緒に設計した方がよい。
- 弓や矢のような、専用スロットを持つ飛び道具。
- アイテムの未識別と識別。
- 合成、店、値段。
- 呪い、装備の外せない状態。
- 持ち物の並び替え、ソート、まとめ表示。
- インベントリ枠数の変更（9枠のまま）。

## 目標体験

- 盾を拾った時に「武器と盾のどちらを優先して持ち帰るか」で少し迷う。
- 巻物を拾った時に「今の装備に使うか、もっと良い装備まで温存するか」で迷う。
- 強化値のついた装備に愛着が出て、置いていくのが惜しくなる。
- 遠くの敵に物を投げて削る、という選択肢が生まれる。
- アイテム種別が7つになっても、持ち物メニューの操作が分からなくならない。
- ログを読めば、何が起きたのか毎回分かる。

## 実装方針

### アイテム基盤の分離

モンスターと同じ二層構成にする。

- `item-catalog.js`: `window.GORO_DUNGEON_ITEM_CATALOG` に、アイテム定義の配列を置く。
- `item-system.js`: `window.GORO_DUNGEON_ITEMS.createSystem(catalog)` で、種別既定値のマージ、表示名の組み立て、効果値の計算を行う。

カタログの1件はこの形にする。

```js
{
  key: "ironSword",
  name: "鉄の剣",
  kind: "weapon",
  icon: "weapon",
  atk: 3,
  maxUpgrade: 3,
  throwPower: 6,
  flavor: "使い込まれているが、刃はまだ鋭い。",
}
```

種別ごとの既定値は `item-system.js` 側に置く。

```js
const KIND_PROFILES = {
  weapon: { label: "武器", actionLabel: "装備", equipSlot: "weapon", upgradable: true },
  shield: { label: "盾",   actionLabel: "装備", equipSlot: "shield", upgradable: true },
  food:   { label: "食料", actionLabel: "食べる", consumable: true },
  potion: { label: "薬",   actionLabel: "飲む",   consumable: true },
  scroll: { label: "巻物", actionLabel: "読む",   consumable: true },
};
```

`main.js` の `itemTypes` は、システムが作る定義辞書をそのまま指すようにする。既存の `itemTypes[type].name` のような参照は壊さない。

### 効果文の生成

`description` を手書きすると、強化値がついた時に表示と実数値がずれる。効果文は個体から計算する。

```js
itemSystem.effectText(item); // "攻撃+3" / "攻撃+4（+1）" / "守備+1" / "満腹度+35"
```

カタログには効果の数値と `flavor` だけを置き、効果文はシステムが組み立てる。数値で表せないもの（巻物）はカタログの `description` で明示的に上書きできるようにする。

### アイテム個体

床の生成も持ち物への追加も、必ず1つの生成関数を通す。

```js
function createItemInstance(type, options = {}) {
  const item = { id: nextItemId, type, upgrade: itemSystem.clampUpgrade(type, options.upgrade || 0) };
  nextItemId += 1;
  return item;
}
```

個体は `{ id, type, upgrade }`、床の個体はこれに `x`, `y` が付く。拾得と設置で `upgrade` を引き継ぐ。

### 装備スロット

`state.player.weapon` を `state.player.equipment` へ置き換える。

```js
state.player.equipment = { weapon: null, shield: null };
```

スロット名はアイテム側の `equipSlot` から引く。装備処理は種別を知らず、スロットだけを見る。

```js
const slot = itemSystem.equipSlotOf(item.type);
if (slot) { state.player.equipment[slot] = item.id; }
```

同じスロットの装備は自動的に置き換える。外す操作は、同じアイテムをもう一度選んだ時の解除とする。

### 守備の反映

被ダメージ計算にあるのは `state.player.def` の直接参照2箇所（反撃と敵の攻撃）。ここを `playerDefensePower()` に差し替える。

```js
function playerDefensePower() {
  return state.player.def + shieldDefenseBonus();
}
```

最低ダメージ1は維持する。盾でダメージ0にはしない。

### 強化値

- 表示名は `鉄の剣+2` の形にする。強化値0では `+0` を付けない。
- 武器の攻撃補正は `atk + upgrade`、盾の守備補正は `def + upgrade`。
- 上限はカタログの `maxUpgrade`（既定3）。上限に達した装備へ強化を使うと、消費はするが上がらない。

### 巻物

最小2種にする。状態異常に依存しないものだけを選ぶ。

- 強化の巻物: 装備中の武器を+1する。武器がなければ盾を+1する。どちらもなければ効果なしで消費する。
- いかずちの巻物: プレイヤーと同じ部屋にいる敵全員へ固定ダメージ。通路にいる場合は周囲2マス以内の敵を対象にする。

対象選択UIは作らない。優先順位はログに出す文言で分かるようにする。

### 投げる

持ち物メニューに `T` を足す。

- 吾郎の向きへ最大6マス飛ぶ。
- 最初に当たった敵へ `throwPower + rng(0,1)` のダメージ。当たったアイテムは失われる。
- 誰にも当たらなければ、経路上の最後の空きマスへ落ちる。落とせる場所がなければ失われる。
- 装備中のアイテムは投げられない。装備を誤って失う操作を1つ減らす。
- 1ターン消費する。

演出は既存 `effects` に `throwItem` を足し、始点から終点へアイコンを補間表示するだけにする。ダメージ適用は即時で、演出は見た目だけとする。

### 満腹度の最大値

`state.player.maxHunger` を状態へ持つ。初期100、上限150。

- 食料の `hunger` は現在値、`hungerMax` は最大値を上げる。
- UI表示は `満腹度 x / y` にする。
- リトライで100へ戻す。

### 敵特効

`monster-catalog.js` の各敵へ `tags` を足し、`monster-system.js` の `createEnemy()` が `enemy.tags` として持たせる。

```js
tags: ["demon"]
```

武器側は `slayer: { tag: "demon", bonus: 6 }` を持つ。プレイヤー攻撃力の計算時、対象の `tags` に一致したらボーナスを足し、ログと浮遊テキストで「特効」を出す。

強化値と特効はどちらも攻撃力に足す。乗算にはしない。

### アイテム表の分離

`dungeon-item-tables.js` を新設し、`floorItemTables` と `treasureRewardTables` を移す。敵側の `dungeon-spawn-tables.js` と同じ形にそろえる。テストからカタログとの整合を検証できるようにするのが主目的である。

| キー | 表示名 | 種別 | 効果 | 位置づけ |
| --- | --- | --- | --- | --- |
| `woodenShield` | 木の盾 | 盾 | 守備+1 | 序盤の基本盾 |
| `ironShield` | 鉄の盾 | 盾 | 守備+3 | 中盤の当たり |

## 出現配分の方針

- 盾は武器と同じくらいの頻度で出す。守備を選ぶ習慣を早く作る。
- 巻物は2Fから低確率で出し、4F以降で少し増やす。
- 大きなおにぎりは4F以降のみ。
- 悪魔斬りの剣は4F以降の最低確率と、強敵の確定報酬にだけ入れる。
- 強敵報酬へ盾、巻物、レア武器を追加する。Topic 4完了メモの「Topic 5で報酬へレア武器、盾、巻物を追加できる」に沿った変更である。

## UIの変更

### ステータス欄

- `装備` を `武器` へ改名し、`盾` の行を追加する。
- 満腹度を `x / y` 表示にする。
- 持ち物一覧は `表示名 / 効果文` を出す。

### 持ち物メニュー

- パネル高さを広げ、9個目の行が説明欄と重ならないようにする。
- 各行に種別ラベルと装備マーク（`武器`／`盾`）を出す。
- 説明欄を2行にし、1行目に `[種別] 効果文`、2行目にフレーバーを出す。
- 操作ヒントを `Enter: 使う/装備  T: 投げる  D: 置く  Esc: 閉じる` にする。

### 床表示

- 盾と巻物のアイコンSVGを追加する。
- 淡い光の色を種別ごとに追加する。
- 画像が読めない場合のCanvasフォールバック形状を盾と巻物に足す。
- レア武器は専用アイコンにして、通常武器と床上で見分けられるようにする。

## テスト方針

`tests/item-system-tests.js` を追加し、Nodeの `vm` でカタログ、システム、アイテム表、遭遇テーブルを読み込んで検証する。

- 種別プロファイルが解決でき、操作ラベルが種別ごとに違う。
- 表示名に強化値が付き、+0では付かない。
- 武器の攻撃補正と盾の守備補正に強化値が乗る。
- 強化値が `maxUpgrade` を超えない。
- 特効がタグ一致時だけ乗る。
- 効果文が強化後の実数値を出す。
- 階層別表、宝物部屋表、強敵報酬表のすべての `type` がカタログに存在する。
- 既存アイテムの数値が変わっていない。

既存の `structure-tests.js`、`monster-system-tests.js`、`special-encounter-tests.js` も通ることを確認する。

## 受け入れ条件

- 盾を装備すると被ダメージが減り、ステータスに反映される。
- 武器と盾を同時に装備でき、片方の装備がもう片方を外さない。
- 強化の巻物で装備が+1され、表示名と効果文が更新される。
- いかずちの巻物で同じ部屋の敵にまとめてダメージが入る。
- 持ち物から物を投げて敵に当てられ、外れた物は床に落ちる。
- 大きなおにぎりで満腹度の最大値が上がる。
- 悪魔斬りの剣がミニ悪魔ちゃんに対してだけ強い。
- 持ち物メニューで、7種別すべての操作が破綻しない。
- 追加後もログとUIだけで何が起きたか分かる。
- 既存の4テストが通る。

## 段取り

1. `item-catalog.js` / `item-system.js` / `dungeon-item-tables.js` を作り、既存6アイテムのまま差し替える。挙動が変わらないことを先に確認する。
2. 装備スロットの2枠化と守備反映を入れ、盾2種を追加する。
3. 強化値と巻物2種を追加する。
4. 投げる操作と飛び道具演出を追加する。
5. 満腹度最大値と特効レア武器を追加する。
6. アイコン、メニュー、HUD、説明文を整える。
7. テストとドキュメントを更新する。

段階1で既存挙動を保ったまま土台だけ差し替えるのは、後の段階で不具合が出た時に、原因が土台側か新機能側かを切り分けやすくするためである。

## 残す判断

- 状態異常回復薬と杖はTopic 6へ回す。状態異常がない状態で作ると、効果の設計をやり直すことになる。
- 弓と矢はTopic 5では作らない。専用スロットと残数管理が必要で、持ち物メニューの作り直しになる。
- 投げるは「当たれば消える」で始める。落下位置の厳密なルールは、フロア生成が変わるTopic 7で再検討する。
- 強化値の上限3は暫定値である。深層の実装が入ってから見直す。
