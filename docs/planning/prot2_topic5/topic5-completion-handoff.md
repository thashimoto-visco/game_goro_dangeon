# Topic 5 最小実装完了メモ

作成日: 2026-08-12

## 概要

Topic 5「アイテム体系の拡張」は、アイテム基盤の分離と、盾、巻物、投げる、強化値、敵特効までの最小実装が完了した。

アイテム定義は `main.js` から外へ出し、モンスターと同じ「カタログ（データ）＋システム（挙動）」の二層構成へそろえた。`main.js` はアイテム個別の知識を持たない。

装備は武器1本から武器と盾の2スロットになり、攻撃力以外の装備判断が生まれた。

状態異常に依存する状態異常回復薬と杖は、状態異常そのものが存在しないため、Topic 6へ回した。

## 実装済み

- `item-catalog.js`: 10種のアイテム定義。
- `item-system.js`: 種別プロファイル、表示名、効果文、強化値、特効、投擲威力の解決。
- `dungeon-item-tables.js`: 階層別アイテム表と宝物部屋表。
- 武器と盾の独立した装備スロット。
- 盾の守備補正を反撃と敵攻撃の両方へ反映。
- 装備の強化値 `+0`〜`+3` と、表示名/効果文/投擲威力への反映。
- 同じアイテムを選び直すことによる装備解除。
- 巻物種別と、強化の巻物、いかずちの巻物。
- 持ち物メニューからの「投げる」（`T`）と飛び道具演出。
- 満腹度の最大値と、それを上げる大きなおにぎり。
- モンスターのタグ（`slime` / `beast` / `stone` / `demon`）。
- 悪魔タグへ特効を持つレア武器「悪魔斬りの剣」。
- 盾、巻物、レア武器の専用SVGアイコンとCanvasフォールバック形状。
- 種別ラベル、効果文、フレーバー文を出す2行の説明欄。
- 強敵の確定報酬への盾、巻物、レア武器の追加。
- `tests/item-system-tests.js`。

## 二層構成の役割分担

`item-catalog.js` はデータだけを持つ。

```js
{
  key: "ironShield",
  name: "鉄の盾",
  kind: "shield",
  icon: "shield",
  def: 3,
  throwPower: 5,
  flavor: "重いが、殴られてもへこまない。",
}
```

`item-system.js` は種別ごとの既定値と計算を持つ。

- `KIND_PROFILES`: 種別ラベル、操作ラベル、装備スロット、強化可否、消費可否、既定の投擲威力。
- `displayName()`: 強化値を付けた表示名。`+0` では付けない。
- `effectText()`: 強化後の実数値から効果文を組み立てる。
- `clampUpgrade()` / `canUpgrade()`: 強化値の上限管理。
- `slayerBonusFor()`: 敵タグとの照合。
- `throwPowerOf()`: 投擲威力。強化可能な種別だけ強化値が乗る。

効果文を手書きせず計算する理由は、強化値が付いた時に表示と実数値がずれないようにするためである。数値で表せない巻物だけ、カタログの `description` に `{power}` のようなテンプレートを置き、システムが埋める。

## アイテムの追加方法

既存の5種別であれば、`main.js` を触らずに追加できる。

1. `item-catalog.js` へ1件足す。
2. `dungeon-item-tables.js` の該当階層へ `{ type, weight }` を足す。
3. `node tests/item-system-tests.js` を実行する。出現表の全 `type` がカタログに存在することまで検証する。

新しい種別が必要な場合だけ、以下を足す。

1. `item-system.js` の `KIND_PROFILES` へ、種別ラベル、操作ラベル、装備スロット、強化可否を追加。
2. `main.js` の `useInventorySlot()` へ使用処理を1分岐追加。
3. アイコンを `images.icons` / `sprites.icons` / `ITEM_DRAW.glow` / `ITEM_FALLBACK_COLORS` へ追加。

## 決めた仕様

### 強化の巻物の対象

対象選択UIは作らず、武器を優先し、武器がなければ盾を上げる。

どちらも装備していない場合でも巻物は消費される。上限 `+3` に達した装備へ読んだ場合も消費される。ログでどちらの結果かが分かるようにしている。

### 投げる

- 吾郎の向きへ最大6マス。
- 最初に当たった敵へ `投擲威力 + rng(0,1)` のダメージ。命中した投擲物は失われる。
- 外れた場合は経路上の後ろから順に空きマスを探して落とす。足元も落下先として許可する。
- 装備中のアイテムは投げられない。誤操作で装備を失わないようにするためである。
- 投擲を拒否した場合はメニューを閉じない。別のアイテムを選び直せるようにするためである。
- 1ターン消費する。

「置く」（`D`）は装備中でも可能なままにした。これはTopic 5より前からある挙動で、変更すると既存の操作感が変わるためである。投げるだけを制限した理由は、置くと違って取り返しがつかないためである。

### 満腹度の自然回復しきい値

`recoveryGainForHunger()` のしきい値（90 / 70 / 30）は絶対値のまま残した。

最大値が150になると、しきい値を相対にしない限り「回復が速い状態」に長く留まる。これは大きなおにぎりの利点そのものなので、意図した効果として受け入れた。既存の手動テスト項目もそのまま有効である。

### 盾と最低ダメージ

被ダメージは `max(1, 敵攻撃 - (守備 + 盾補正) + rng(0,1))` である。盾でダメージ0にはならない。

5Fの強敵ミニ悪魔ちゃん（攻撃8）に対し、レベル3（守備3）＋鉄の盾（+3）で被ダメージは2〜3になる。無防備時の5〜6から半減するが、無傷にはならない。

## 残した判断

- 状態異常回復薬と杖はTopic 6へ回した。状態異常がない状態で作ると効果設計をやり直すことになる。
- 弓と矢は作らない。専用スロットと残数管理が必要で、持ち物メニューの作り直しになる。
- 未識別、呪い、合成、店は入れない。
- 持ち物の並び替えとまとめ表示は入れない。9枠のままで破綻していない。
- 強化値の上限3は暫定値である。深層が実装されてから見直す。
- 投擲物の落下ルールは単純なままにした。フロア生成が変わるTopic 7で再検討する。
- 投擲に敵特効は乗せていない。特効は装備して振る武器の価値として残した。

## 次Topicへの引継ぎ

- Topic 6で状態異常を入れたら、`item-catalog.js` へ状態異常回復薬を1件足すだけで済む。`KIND_PROFILES` の `potion` をそのまま使える。
