# Topic 7 完了メモ: マップ生成の強化

完了日: 2026-08-20

レビュー修正日: 2026-08-20

## 実装したもの

- `floor-theme-catalog.js` に標準、大広間、小部屋群の生成条件、表示、配置係数を集約した。
- `dungeon-theme-tables.js` に階層別の重み付き配分を追加した。1Fと2Fは標準固定、3F以降は小部屋群、6F以降は大広間も候補になる。
- `dungeon-layout.js` はテーマ名を知らず、外部から受け取った部屋数、サイズ、余白、特徴部屋、追加接続率、階段距離だけを使う構造にした。
- 大広間では15〜19×9〜12の特徴部屋を通常部屋より先に配置する。
- 通常部屋が存在する場合は特徴部屋を開始候補から除外し、大広間が敵・アイテム配置候補に残るようにした。
- イベント部屋の最小サイズをテーマデータから渡せるようにし、小部屋群では5×4へ緩和した。
- 敵とアイテムの基本出現数へテーマ係数を適用した。大広間は敵1.15倍、アイテム1.2倍である。
- テーマ固有の暗闇色、階段移動カードのテーマ名・到着文、階層移動ログを追加した。標準テーマでは従来の階層深度色を維持する。
- ローカル限定デバッグクエリ `?debug=1&floor=8&theme=greatHall` を追加した。未知のテーマキーは標準へ戻る。

## 互換性

テーマ未指定の `buildFloorLayout()` は従来の既定値を使う。固定シード12345で20層をJSON化したSHA-256は、変更前後とも `3a14e250d57686803d20123b20e4686957789a8066cff59ccb89afd71e190567` で一致した。

1Fと2Fのテーマ表は標準1件だけであり、テーマ決定時に乱数を消費しない。このため操作習得段階の生成順も変えない。

## 自動確認

- `tests/floor-theme-tests.js`: カタログと配分、1F/2F固定、最小部屋寸法、余白、未知キーの標準フォールバック、イベント部屋条件を確認した。
- `tests/structure-tests.js`: 全テーマを各200シード生成し、到達性、出入口、通路、視界分離、フォールバック率、強敵候補、イベント候補を確認した。
- 大広間の全200シードで、特徴部屋が開始部屋にならず、敵・アイテムの配置候補に残ることを確認した。
- レビュー再現条件と同じ300シードの追加実測でも、特徴部屋が開始部屋になった件数は0/300だった。
- `tests/app-startup-tests.js`: DOM/Canvas差し替え環境で3テーマと未知キーを起動し、テーマ固定、マップ寸法、特徴部屋、敵・アイテム・階段・イベント配置、公開ホストでのデバッグ無効化を確認した。
- フォールバック: 標準0/200、大広間0/200、小部屋群0/200。
- 強敵候補: 標準200/200、大広間200/200、小部屋群194/200。
- イベント候補: 標準147/200、大広間165/200、小部屋群194/200。
- 既存6テスト（構造、モンスター、特殊遭遇、アイテム、状態異常、敵AI）と新規2テストがすべて通過した。
- 大広間15×11の可視範囲計算は10,000回で約249ms（1回約0.025ms）で、標準5×6の約0.006ms/回に対して実用範囲だった。
- 全JavaScriptの `node --check`、`git diff --check`、HTMLスクリプトの実在・大文字小文字、root-absoluteなアセット参照がないことを確認した。GitHub Pages上の期待URLは `https://thashimoto-visco.github.io/game_goro_dangeon/assets/...` となる。

ブラウザ実機確認は未実施。同梱ブラウザ制御の初期化が、プラグイン側の信頼済みパス設定エラーで失敗したためである。見た目、カメラ、遷移カードの最終確認は `../prot1/manual-test-checklist.md` の「フロアテーマ」を使って行う。

## 残した判断

- 水路、穴、迷路、隠し部屋、非矩形部屋、部屋内障害物は実装していない。
- フロアサイズ40×30、部屋間余白3、最大特徴部屋19×12は変更していない。
- テーマ固有タイルやBGMは追加していない。
